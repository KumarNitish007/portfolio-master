Engineering notes
RBAC layered over a live legacy schema

Menu-, project- and button-level permissions built on top of the existing portal tables without changing them. One stored procedure (usp_RBAC_Manager) drives everything; Angular directives enforce it and an admin screen manages it.

Fail-closed approvals, idempotent roll-ups

The Approve / Reject control only renders for users holding the approver grant. Quantities are recomputed by SUM across approved releases, so repeated approvals never double-count.

Login against real portal accounts

Authenticates against the existing user and employee master with the portal's own encryption functions; refresh tokens live in a separate table so portal data is never modified.

Performance & delivery

Diagnosed slowness as network-bound rather than SQL-bound and applied response compression and connection-pool warm-up. GitHub Actions CI/CD, plus an Electron installer with bundled SQLite for offline use.

Engineering notes
Hardware-based device identity

Endpoints are identified by a fingerprint built from BIOS, baseboard and network identifiers rather than a hostname. Device secrets are issued once, stored PBKDF2-hashed on the server and DPAPI-encrypted on the endpoint.

Two token audiences, zero cross-talk

Portal users and device agents get separate JWT audiences, and a DeviceSelf policy guarantees an agent can only post as itself — cross-device calls return 403.

GPS from a Windows service

Services can't read Windows Location from session 0, so the agent installs a per-user scheduled task that captures a real GPS fix in the user session and hands it back; any non-satellite fix is rejected rather than guessed.

Field-tested reliability

Caught and fixed an Active Directory email-lookup hang on non-domain machines (domain check plus a 5-second timeout). 20 automated tests on in-memory SQLite, and per-environment MSIs for dev, test and production.
